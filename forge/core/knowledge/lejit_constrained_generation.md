# LeJIT：约束感知的表格生成（HotNets'25）要点摘要

> 本文为规则卡 RAG 知识库素材，提炼自 docs/行动计划报告.md 第 1、4、5 节
> （论文原文见 papper/ 目录 HotNets'25 LeJIT）。

## 约束解码原理

LeJIT 在 Hugging Face causal LM 之上做**逐步约束解码**：表格行按字段拓扑序
序列化为 token 流，模型每生成一个字段值，Z3 即时检查"当前前缀 + 候选值"
与 NetNomos 规则库（rules.json）是否可满足；不可满足的候选被过滤，模型只能
在可行域内继续采样。因此 B 轨生成的每一行都**构造性地满足全部启用规则**，
而不是生成后再筛选。训练产物是自包含 bundle（模型权重 + schema + 规则）。

## 双轨对比方法论

A 轨（裸模型）：同一 prompt 直接让通用 LLM（如 qwen2.5）生成记录或撰写
报告。LLM 对协议物理规律、会计勾稽关系没有任何校验能力，会稳定出现：
- 网络：UDP 流量携带 TCP Flags、Packets×65535 < Bytes（超物理上界）、
  端口 53 出现在非 DNS 身份主机；
- 财务：照抄资料中的错误数字，并用错误数字连带算错毛利率等衍生指标。
B 轨（规则约束）：网络走 LeJIT 约束解码；财务走"validate 命中违规 →
Projector 数值投影修正 → 衍生指标程序计算 → 模板槽位回填"。
两轨同屏标红对比即产品核心叙事："不改模型，只加规则"。

## 财务 B 轨：投影与槽位回填

财务报告不走 LeJIT 训练（表格小、中文长文为主），采用确定性管线：
1. validate：规则集 × 资料包 → 逐行违规清单（行号/字段/期望值）；
2. Projector：对恒等式违规求修正值（如"营业成本应为 2,000 =
   期初存货 10,000 + 采购 4,000 - 期末存货 12,000"），宿主机可用 Z3
   求最近可行解；比率背离类只出风险提示；
3. 槽位回填：报告正文模板只允许 {{slot}} 槽位，全部数值由程序写入；
4. 终检：正则扫描正文，残留未回填槽位或"槽位白名单之外的裸数字"
   一律告警——杜绝 LLM 在长中文报告里抄错数字的风险。

## 犯错稳定性与可复现

演示要求"裸模型稳定犯错但报告像样"：temperature/seed 固定 +
prompt 种子库预筛（只保留稳定复现错误的 prompt 版本），杜绝"裸模型
偶然不犯错"导致对比失效。错误注入器输出真值表（错误单元格的
错误值/正确值/命中规则），供自动验收与 diff 标红对齐。
