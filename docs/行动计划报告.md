# NetNomos-Forge 项目行动计划报告

版本：v1.0 ｜ 日期：2026-06-13 ｜ 状态：待评审

## 0. 摘要

netnomos-forge 是把 NetNomos（规则挖掘）和 LeJIT（约束生成）能力产品化的演示工程，交付"数据上传 → 规则自发现 → 规则解释 → 规则入库 → 复用核查 → 合规报告 → 双轨标红对比"完整闭环，覆盖网络与财务两个场景，并以 Web 产品页（介绍页 + 两个 demo）作为主演示载体，marvis 3D 多 Agent 办公室作为可选趣味界面。

开发采用多 Agent 协作模式：由 Orchestrator（fable）统一拆解任务并做模型路由——方案设计、核心业务代码、代码审查用 fable；Web 设计实现用 opus；数据搬运等机械性工作用 sonnet/haiku；规则解释与报告正文由本地 ollama / codex 在运行时承担。

总开发周期 6 周（W0–W5），每周有明确交付物和验收标准。

## 3. API 再封装设计（目标 1/3 的核心）

封装原则：上层代码只面向 forge SDK，不直接 import netnomos/lejit 内部模块；每个方法可独立测试、有类型注解、产物落盘格式统一，便于阅读与多 Agent 并行开发。

### 3.1 ForgeRuleEngine（封装 NetNomosMiner）

```python
engine = ForgeRuleEngine.from_scenario("network_cidds")   # 加载 DatasetSpec+GrammarSpec
rules  = engine.learn(data_path, learner="hitting-set")   # → RuleSet（含落盘 rules.json）
report = engine.validate(new_data, rules)                 # → ViolationReport（行号/字段/命中规则）
ok     = engine.check(rules, "Proto=UDP -> Flags=noflags")# entails 断言复核
cards  = engine.explain(rules, lang="zh")                 # interpret + LLM 规则卡
```

### 3.2 ConstrainedGenerator（封装 LeJIT）

```python
gen = ConstrainedGenerator.train(scenario, base_model, rules)  # lejit train → bundle
rows = gen.generate(n=10)                                      # 每步 Z3 过滤的合规记录
rows = gen.complete(prefixes)                                  # 前缀补全
```

### 3.3 财务专用层

财务不走 LeJIT 训练（表格小、中文报告为主），采用"LLM 起草 + 规则校验 + 数值投影 + 程序回填"：FinanceValidator（基于 ForgeRuleEngine.validate）→ Projector（Z3 求最近可行解，如"营业成本应为 2,000"）→ Reporter 槽位回填（正文只允许 {{slot}}，数值全部由程序写入，终检正则扫描残留裸数字）。

### 3.4 REST 接口（沿用 plan 表 7）

/api/rulesets/upload、/api/data-sources、/api/rulesets/learn、/api/rulesets/{id}/cards、/api/reports/generate、/api/workflow/events/stream (SSE)、/api/chat/constrained。SSE 事件即 marvis 的 WorkflowEvent 结构，前后端共用一份 schema。

## 4. 网络场景实施方案（目标 1）

数据：规则学习用 NetNomos 自带 cidds_wk2_normal_10k.csv（低风险、已有 golden rules 对照）；复用核查用 net_data/cidds_wk3_all.csv 抽样 5–10 万行作"新上传流量"；pcap 演示用 netflix.pcap / mawi（marvis 前端可直接解析展示）。

流程：learn → 规则画像（范围/物理上下界 65535×Packets≥Bytes、42×Packets≤Bytes / 协议蕴含 UDP→noflags / 部署规律 SrcPt=53→dns）→ 规则卡解释 → 对 wk3 新数据 validate 输出违规清单 → 生成《网络流量审计与遥测健康报告》。

双轨对比：A 轨裸模型（ollama）用相同 prompt 生成 10 条 NetFlow 记录，预期出现 UDP 带 TCP Flags、Packets×65535<Bytes 等错误并标红；B 轨 LeJIT bundle（4090 训练）按字段拓扑序生成，每步过 Z3，附规则通过与干预日志。

验收：训练集规则满足率 1.0；A 轨 10 条中稳定出现 ≥3 类协议/物理错误；B 轨 0 违规；报告中全部数值由程序回填。

## 5. 财务场景实施方案（目标 2）

### 5.1 数据生成

合成训练集：3 行业（咨询/零售/制造）× 40 公司 × 8 报告期 = 960 行，金额千元整数。生成器按恒等式正向推导（COGS=Revenue×(1−毛利率)、Purchases=COGS+ΔInventory、TotalAssets=Cash+Inventory+AR+Other、TotalLiabilities=TotalAssets−TotalEquity、下期期初=本期期末），训练集天然满足全部规则；行业参数差异化（咨询存货占比 <2%、零售 15–30% 等）让 NetNomos 学出行业蕴含式。派生字段（GrossProfit、InventoryToAssetsBp、ReceivableToRevenueBp 等）把多元恒等式折叠为二元规则便于学习。中文列名经 source_name 映射，规则学习用英文规范名。

### 5.2 错误注入（诱导错误）

确定性注入器生成"华信咨询"待审资料包：F1 进销存恒等式破坏（成本写 3,000 应为 2,000）、F2a 跨期现金断裂（8,500 vs 8,000）、F2b 资产负债表不配平（差额 500）、F3 行业异常（咨询存货占比 35%）、F4 应收 +300% vs 营收 +15%。注入器输出"错误清单真值表"用于自动验收。

### 5.3 双轨对比报告

A 轨：裸模型读取错误资料直接撰写《年度财务分析与审阅报告》，照抄错误并连带算错毛利率等衍生指标 → 前端标红。B 轨：先 validate 命中 F1–F4 → Projector 修正口径 → 衍生指标按修正值程序计算 → 正文槽位回填并引用规则卡 → 附录输出核查与干预日志。

兜底：若自动学习未稳定产出关键恒等式，启用人工规则通道（同 rules.json 格式注入 R01/R02/R05），叙事改为"机器发现 + 专家补充"。

## 6. 诱骗（A 轨裸模型）选型方案（目标 5 要求）

约束：宿主机 ollama + 2×4090（24GB×2），需要本地、可复现、"稳定犯错但报告像样"。

| 用途 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 财务 A 轨中文报告 | qwen2.5:14b-instruct（单卡） | qwen2.5:32b-q4（双卡/更高文采） | 中文财报写作流畅、可信度高，但对勾稽关系无校验，会忠实照抄注入错误——演示反差最佳 |
| 网络 A 轨 NetFlow 生成 | qwen2.5:7b/14b | llama3.1:8b | 小模型更易犯协议/物理错误，且与 B 轨形成"同等条件"对比 |
| B 轨 LeJIT 基座 | LeJIT 默认小型 causal LM（4090 单卡训练） | — | 论文同款路线，训练成本低 |
| 规则卡解释 / 正文起草 | codex（已登录） | qwen2.5:32b / DeepSeek API | 解释质量要求高；只写文字不定数值，无合规风险 |

犯错稳定性保障：temperature 固定 + seed 固定 + prompt 种子库预筛（挑选稳定复现错误的 prompt 版本入库），杜绝"裸模型偶然不犯错"导致对比失效。

## 7. 多 Agent 开发组织与模型路由（目标 4 + 要求）

### 7.1 开发期 Agent 编制

| Agent | 模型 | 职责 |
|---|---|---|
| Orchestrator/Router | fable | 任务拆解、依赖排程、判断每个子任务该用什么模型、验收合并 |
| Architect | fable | forge SDK 接口设计、schema/事件协议定稿 |
| Core-Dev | fable | engine/generator/projector/injector/reporter 等核心业务代码 |
| Data-Agent | sonnet/haiku | 数据搬运、抽样、格式转换、批量脚本、环境安装 |
| Web-Dev | opus | 产品介绍页、两个 demo 工作台、双轨标红 diff UI |
| Explainer-Dev | fable | RAG 规则卡管线（运行时由 codex/ollama 执行推理） |
| Reviewer | fable | 代码审查、安全审查、验收脚本复核（独立于编写者） |

路由规则（Orchestrator 执行）：涉及接口契约/数值正确性/Z3 逻辑 → fable；UI/视觉/交互 → opus；可一步描述清楚的机械任务 → sonnet/haiku；运行时推理（解释、起草、诱骗）→ ollama/codex 本地模型，不消耗 Claude 配额。

### 7.2 运行/演示期 Agent（映射 marvis 角色）

主管A=Orchestrator（接收规则集/总控）、快递B=数据搬运（上传/解析 pcap、csv）、员工C=规则生成（NetNomos learn）、员工D=规则解释与验证（interpret+validate+规则卡）、员工E=插件/报告制作（双轨报告、diff）、产品经理F=受约束聊天（/api/chat/constrained）。后端每个 pipeline 阶段发 WorkflowEvent（agent/stage/status），同一条 SSE 流同时驱动 Web 工作台进度与 3D 办公室动画——marvis 接入零额外业务逻辑。

## 8. Web 产品展示页（目标 6）

技术栈 React+Vite+TS（与 marvis 同栈，组件可互用）。三个页面：

1. 介绍页：定位口号（"不改模型，只加规则"）、痛点叙事、三大价值（规则自发现/合规生成/复用核查）、架构图、双场景入口；
2. 网络 demo：上传/选择数据 → 规则学习进度（SSE）→ 规则画像与规则卡 → 新数据核查违规清单 → 双轨 NetFlow 对比标红 → 审计报告预览下载；
3. 财务 demo：合成数据预览 → 规则学习 → 上传"华信咨询"错误资料包 → F1–F4 命中展示 → 双轨报告对比（错误行标红 vs 规则通过+干预日志）→ 报告下载。

3D 办公室作为第四入口（可选），iframe/路由集成 marvis product，仅消费同一 SSE 流。

## 10. 风险与对策
