# NetNomos：声明式网络规则挖掘（NSDI'26）要点摘要

> 本文为规则卡 RAG 知识库素材，提炼自 docs/行动计划报告.md 第 1、4 节
> （论文原文见 papper/ 目录 NSDI'26 NetNomos）。

## 规则挖掘原理

NetNomos 从原始表格数据（如 NetFlow CSV）中自动挖掘结构化逻辑规则。
核心流程：DatasetSpec 描述字段与预处理 → GrammarSpec 限定候选公式文法 →
学习器（hitting-set：C++/Python 双后端；tree：决策树式归纳）枚举候选规则 →
Z3 求解器逐条校验候选规则在训练集上的满足率（support / confidence），
满足率达标者进入规则库 rules.json。与黑盒模型不同，每条规则都是可读、
可验证、可人工开关的逻辑公式。

## 物理上下界规则

NetFlow 数据天然受物理规律约束，NetNomos 能从数据中复原这类上界/下界：
- 65535 × Packets ≥ Bytes：单个 IP 包最大长度 65535 字节，一条流的总字节数
  不可能超过包数乘以最大包长；
- 42 × Packets ≤ Bytes：以太网帧最小有效长度约 42 字节，总字节数不可能低于
  包数乘以最小帧长。
违反任一上下界的流量记录在物理上不可能存在，必为生成/采集错误。

## 协议蕴含规则

传输层协议语义在数据中表现为蕴含式：
- Proto=UDP → Flags=noflags：UDP 是无连接协议，没有 TCP 的 SYN/ACK/FIN
  标志位，UDP 流量携带 TCP Flags 必为伪造或解析错误；
- Proto=ICMP → 端口字段无服务语义。
此类规则是"裸模型生成 NetFlow 常犯"的典型错误，约束生成（LeJIT）可以
在解码每一步用 Z3 过滤掉违反协议蕴含的 token。

## 部署规律规则

特定部署环境会沉淀出站点级规律（deployment regularity）：
- SrcPt=53 / DstPt=53 → 对端为 DNS 服务身份（CIDDS 数据集中 DNS 服务器
  以 "DNS" 标识）；端口 53 出现在非 DNS 身份的主机上即为端口-身份背离；
- 内网网段（192.168.x.x）与子网编号映射固定。
部署规律的支持度高但泛化范围限于同一部署，跨环境复用时需人工确认。

## 支持度与疑似巧合规则

support（支持度）= 满足规则的行数占比；confidence 用于蕴含式右侧条件命中率。
当一条规则包含**过于具体的常量**（如某个偶然出现的端口号、IP 整数编码）
且支持度/出现次数偏低时，应判定为"数据采样巧合"而非真实领域约束——
规则卡上标记【疑似巧合】并在前端置灰，由人类专家决定是否启用。
经典反例：golden 规则集中的物理常量（65535、42、53、80、443）支持度恒为
1.0，属于真实约束，不应被巧合过滤误伤。

## 财务报表中的结构化规则（勾稽恒等式）

同一套挖掘框架适用于财务表格：会计恒等式即"财务领域的物理定律"：
- R01 进销存勾稽：期末存货 = 期初存货 + 本期采购 - 营业成本；
- R02 资产负债配平：资产总计 = 负债总计 + 所有者权益；
- R03/R04 跨期滚动：下期期初存货/现金 = 本期期末存货/现金；
- R05 毛利恒等式：毛利润 = 营业收入 - 营业成本。
行业画像规则（如咨询业存货占总资产 <2%、零售业 15–30%）与比率背离规则
（应收增速不应大幅背离营收增速）属于"账面可自洽但业务异常"的软规则，
违反时出具风险提示而非数值修正。核心恒等式若未被自动学出，可经人工规则
通道以相同 rules.json 格式兜底注入（叙事为"机器发现 + 专家补充"）。
